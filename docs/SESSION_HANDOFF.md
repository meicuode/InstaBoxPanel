## 最新需求与续接状态

文件管理已于本轮提交并推送 `dd92984ee62d3c6670099266bb47957104ce236e`。用户随后要求支持超过 100 MB 的文件，询问分片后如何合并及 95 MiB 限制来源，并明确质疑 Python 依赖。已解释：95 MiB 为面板应对 CF 单请求 100 MB 限制的阈值，InstaBox 单次上传接口为 5 GiB；合并可通过已有 `/exec` 在 InstaBox 机器上进行。本轮未安装 Python，仅曾查询本机 WSL 已有 Python 版本，最终实现完全不依赖 Python。

当前新增分片上传：95 MiB 以上自动切成 16 MiB 分片，单文件最多 20 GiB；浏览器和服务器校验各片 SHA-256，机器上的固定 bash/coreutils/flock 脚本在后台合并并计算完整哈希，再原子发布目标。账号/机器绑定的加密票据与现有登录鉴权并用，无新增 D1 表。浏览器保存续传元数据，重选原文件可跳过已验证的分片，支持清理任务临时目录；合并中取消浏览器等待不保证停止机器上的合并。大文件最终目标不允许符号链接。实现与空间占用说明已更新至 [文件管理](FILE_MANAGEMENT.md)。

本轮分片功能通过：`npm test` 104 项、`node tools/browser-check.mjs` 25 组；浏览器报告 `errors` 为空。`node --import tsx tools/upload-assembly-check.mjs` 在本机 WSL Ubuntu 实际合并了 128 MiB 二进制文件，并通过 6 组分片顺序、完整 SHA-256、重复分片、同名保护、损坏／缺失分片、中断合并和清理重试检查。`npm run build` 与 `npm run worker:check` dry-run 通过。

本轮已将分片改进提交并推送至 `origin/main`；提交号及最终推送结果以 Git 记录和当前会话答复为准。没有部署或连接真实机器。原有未跟踪的安装、安全审计文档和图片未改动或纳入提交。
