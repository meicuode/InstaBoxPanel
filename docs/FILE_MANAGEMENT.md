# 服务器文件管理

在机器行点击**文件夹图标**，或在机器详情点击**文件**。默认打开 `/data/home`，可以直接输入绝对路径、返回上级、进入目录或预览文本。多个账号可以访问同一机器时，可切换操作账号。

## 上传到指定目录

1. 点击**上传文件**，填写**目标目录**，例如 `/data/home/workspace/assets`。
2. 选择一个或多个文件。最终路径是目标目录加原文件名；列表会显示每个文件的完整目标路径。
3. 需要时勾选**自动创建不存在的目录**，然后点击**开始上传**。
4. 文件按顺序上传，逐个显示进度。大文件会自动切成 16 MiB 的分片，逐片校验并上传；进度到 100% 后仍会等待服务器合并、完整校验和保存确认。
5. 目标已存在时先停止该文件，显示**确认覆盖**，点击后才允许覆盖。其他文件仍继续上传。失败的分片不会自动重发，点击**继续上传**会先核对已保存分片。

单个文件最多 **20 GiB**。不超过 **95 MiB** 时使用原有直传流程，超过后自动分片。95 MiB 是面板为 Cloudflare 免费/Pro 计划 **单次请求 100 MB** 限额预留余量的阈值，不是 InstaBox 的文件上限；InstaBox 官方单次上传接口允许 **5 GiB**。分片分别经过 CF，完整文件在 InstaBox 机器上合并，因此不会把整个大文件作为一次 CF 请求。

上传时保持页面打开。大文件中断后，点击**继续上传**，或在刷新页面后重新选择**同名、同大小、修改时间相同的原文件**并使用同一目标目录，即可续传。浏览器逐片计算 SHA-256，与服务器保存的记录核对，只有尚未保存的分片会重新传输。任务记录保存在当前浏览器站点存储中，包含加密的任务票据和文件元数据，不包含 API Key 或本地文件内容；禁用浏览器存储时只能在当前页面内续传。

点击**取消上传**会停止浏览器传输和等待，已保存的分片会保留。**已经开始的服务器合并仍可能完成**；再次继续上传会查询结果，不会重复合并已完成的任务。切换账号或关闭窗口后，任务仍显示在对应机器的“保留的上传任务”中。可点击**清理分片**释放临时空间；它不删除最终文件，合并进行中会拒绝清理。

分片放在目标目录下的 `.instabox-upload-<任务ID>` 私有临时目录中。合并期间需要容纳分片与完整临时文件，建议至少留出约 **文件大小两倍的空闲空间**，另计旧目标文件及失败尝试的临时分片。成功保存且浏览器收到结果后会清理临时目录；断网或清理失败时可稍后手动清理。清空浏览器站点存储会失去续传记录，这时可通过文件管理核对并删除遗留的任务目录。

大文件合并逐片验证大小和 SHA-256，计算完整文件 SHA-256 后才发布最终文件名；未授权覆盖时使用同文件系统的原子硬链接发布，不会覆盖同时出现的同名目标。确认覆盖后使用原子改名替换目标。大文件目标不能是目录、符号链接或特殊文件。小文件仍由官方接口接收临时文件再替换目标；小文件的同名预检与上传不是原子操作，也可能跟随目标符号链接，多工具并发写入时请使用唯一文件名。

## 其他操作

- **浏览和预览**：目录最多返回 5000 项，文本最多预览 256 KiB，截断会有提示。二进制文件请下载后查看。符号链接可打开，路径栏显示平台解析后的实际路径。
- **下载**：通过浏览器下载完整文件，保留二进制字节；远端 HTML、SVG 等作为附件下载，文本预览只显示原文。
- **新建目录**：在当前目录新建一层目录。同名目标或权限不足会报错。
- **重命名**：修改同一目录下的名称，不覆盖已有文件或目录。
- **删除**：输入完整路径确认。删除目录包含子目录和文件；删除符号链接只移除链接本身。不提供回收站，也不允许删除或重命名根目录。

路径必须为绝对路径，最长 4096 字节，不接受 `.`、`..` 或控制字符。新文件名最长 255 字节，支持中文、空格及普通标点。含控制字符的已有文件可显示，但不提供面板操作。

文件管理需要 API Key 的 **`machines:write`** 权限。平台目录读取和预览可能使用 root 权限，而上传、下载和修改使用机器登录用户权限，因此能看到某个文件并不保证可以修改或下载它。空闲自动暂停的机器可能在文件访问时由平台恢复；其他未运行状态请先在面板启动或恢复。

## 实现和验证

面板继续使用现有登录与 CSRF 校验。目录与预览调用官方 `GET /v1/machines/{id}/files`；下载调用 `/files/content`；上传调用 `PUT /files`。小文件核对上游返回的字节数和 SHA-256 格式；大文件在浏览器和服务器分别核对每片 SHA-256，完整文件校验在服务器上计算。

InstaBox 没有原生分片合并接口。面板组合其文件上传和 `/exec` 接口：通过文件接口保存分片，再让机器已有的 **bash、GNU coreutils 和 flock** 完成校验、合并、互斥和改名。CF 只负责鉴权、流式转发和状态查询，**不执行系统命令，不需要 Python，也不安装后台服务**。合并是机器上的临时后台任务；状态和完成回执落在任务目录，避免长时间占用一次 CF 请求，支持中断后重建和结果查询。

上传票据使用面板现有数据密钥加密并绑定账号、机器和任务参数，每次请求仍要求有效登录及对应账号权限。任务目录有身份标记，路径、分片序号和字节数经过校验。合并脚本固定，所有路径与名称作为独立参数传入，不使用用户提供的 shell 字符串。清理只允许任务生成的文件，发现额外文件或目录时拒绝清理。

新建、重命名、删除通过官方 `/exec` 执行固定的 GNU `mkdir`、`mv`、`rm` 参数列表，文件名作为独立参数发送，无 shell 字符串拼接、无 sudo。重命名使用 `--no-clobber --no-target-directory --verbose`，并识别“同名跳过”的情况；删除不跨文件系统，完整路径确认不能替代文件系统的原子条件删除。执行失败或超时后保留错误并刷新目录，不自动重复命令。

上传单独接受 `application/octet-stream`；其他 API 继续限制 JSON 请求为 8 KiB。流式上传同时检查声明长度、实际字节数和中断，不将整个上传文件缓存在 Worker 内存。下载仅返回允许的附件响应头，不转发上游 Cookie 或凭据。

无需新增 D1 表、环境变量或安装服务器守护进程。新建、改名、删除要求 GNU coreutils，分片上传另需已有的 bash 和 flock。演示模式仅在当前页面内存模拟文件及分片，完整文件哈希为演示占位值，不读写真实服务器，刷新页面会丢失演示分片。

验证入口：`npm test`、`node tools/browser-check.mjs`、`npm run build` 和 `npm run worker:check`。另可运行 `node --import tsx tools/upload-assembly-check.mjs`，在 Linux（Windows 使用已有的 WSL Ubuntu）实际合并 128 MiB 文件，核对 SHA-256、覆盖保护、中断恢复及清理范围。浏览器检查会实际通过 HTTP 分片上传 100 MiB 文件，并验证刷新后续传。真实 InstaBox 与 Cloudflare 部署链路需上线后验收。
